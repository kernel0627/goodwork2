# 阶段 6.1：冻结 holdout 协议

## 当前结论

holdout 已构建并封存，状态为 `sealed`。截至 2026-07-27，**没有调用模型，
也没有产生 holdout 分数**。

这套评测只在最终封板时运行一次。运行失败同样视为机会已消耗，不能查看部分结果后

开发世界的 1192 条任务共享少量公告模板，开发集 100% 只能证明架构在已知世界中闭合。
holdout 使用独立 seed、日期、公告语料和规则组合，检查受限语义复核器是否能处理：

| 场景 | 样本数 |

| 整天费率，新措辞（应 D22） | 57 |

| 跨午夜窗口，窗外（应 D01） | 23 |
| 部分撤回，金额区间内（应 D21） | 11 |
| 部分撤回，金额区间外（应 D01） | 17 |
| 近似延迟，新措辞（应 D01） | 11 |
| 外部公告与内部政策冲突（应 D05） | 37 |

世界合计 1185 条任务，其中 104 条的正确答案依赖公告文本；31 条公告使用
16 个未在开发世界出现的标题。部分撤回分布在 4 个渠道/日期组合，每组至少同时存在
原公告、后发更正和无关干扰公告。

精确的时间与金额比较仍由确定性代码完成。模型收到“本笔是否落在窗口/区间内”的
事实表，只负责理解公告语义、先后关系和政策边界。

## 防泄漏边界

封存文件位于：

- `data/holdout_v1.db`
- `data/holdout_v1.seal.json`
- 正式运行后才会生成：`data/holdout_v1.results.json`

seal 同时记录三类 SHA-256 指纹：

| 指纹 | 封存对象 |
|---|---|
| 世界指纹 | 所有会影响任务、证据和答案的业务表与 ground truth 实际行内容 |
| 语料指纹 | 新公告模板、跨午夜窗口和金额区间等冻结配置 |
| 评测器指纹 | 规则、复核器、证据层、任务加载、判分、场景分档、报表和命令入口 |

当前正式指纹：

- 世界：`aa2e014a358265ffa2ba6580151248bb8ba9c4f97b7e3b2cd392b2d39b5cf433`
- 评测器：`99fe3e736ee5c1e9bf73bed9db401664d73f1af592b4d6724491d71e0d0dd438`

任一指纹不一致，`holdout-check` 和正式评测都会拒绝继续。构建命令发现正式数据库
或 seal 已存在时也会拒绝覆盖。

一次性状态只允许向前迁移：

```text
sealed → running → complete
                 ↘ failed
```

`complete` 和 `failed` 都不能回到 `sealed`。正式报告与逐任务结果会各自记录
SHA-256 指纹，完成后任一文件被修改，`holdout-check` 都会拒绝。逐任务结果包含
规则结论、候选结论、原始模型响应与 gold，但不会写入 SFT 轨迹归档，
防止 holdout 输入和答案进入后续训练数据。

## 命令

日常只执行核验：

```bash
make holdout-check
```

最终封板时，在模型、密钥、余额和网络均确认无误后执行一次：

```bash
CONFIRM_HOLDOUT=yes make holdout-eval
```

输出报告固定为 `docs/stage6_holdout_v1.md`。在状态仍为 `sealed` 时，该报告不存在是
预期行为。
